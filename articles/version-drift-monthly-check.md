先週、毎日使っている CLI が1ヶ月半も古いままだったことに気づきました。自動更新がいつの間にか切れていて、46バージョン遅れていた。

そのときに「自動更新は勝手に戻さない。代わりに月1回、自分で確認する」と決めたんです。切ったのが過去の自分の意図的な判断かもしれないので、設定は触らずに運用でカバーしようと。

今日、その6日後に見てみました。**もう6バージョン遅れてました。**

## 測ったもの

- 手元のバージョンと、公開されている最新版の差
- 公式の診断コマンドは、その差を教えてくれるのか
- そもそもリリースはどれくらいの頻度で出ているのか

## 結果

| 見たもの | 実測 |
|---|---|
| 手元 | 2.1.304（10/19 公開） |
| 最新 | 2.1.310（10/23 公開） |
| 差 | 6バージョン / 4日 |
| 直近30日のリリース数 | 25回（約29時間に1回） |
| 診断コマンドの判定 | **「No installation issues found」** |

## いちばん効いたのは、診断コマンドが「問題なし」と言ったこと

公式の診断コマンドを走らせると、入っているバージョンも「自動更新: 無効」も、ちゃんと表示されます。
でも**最新版と比べていない**。だから6バージョン遅れた状態で「問題は見つかりませんでした」と出る。

しかも「最後の更新: 成功 → 2.1.258（9/2）」という行があって、これは2ヶ月前の記録なんですよ。先週手で入れた 2.1.304 は「更新の試行」として記録されていない。この行だけ読むと、9月から何もしていないようにも見える。

嘘は言っていないんです。でも、**こちらが知りたいこと（遅れているか）には答えていない**。

先週の自分は「月1で診断コマンドを叩けば大丈夫」と思っていたけど、それ単体では永遠に「問題なし」しか返ってこなかった。別のコマンドで最新版を調べて、目で見比べて初めて分かる。片方だけやると素通りします。

## 「月1」という頻度も間違っていた

30日で25リリース。だいたい29時間に1本出ている計算です。

これに対して月1回の確認だと、最悪で25バージョンぶん遅れた状態で1ヶ月走ることになる。実際、先週直したときは46バージョン遅れでした。月1運用を続けても、同じ規模の遅れがまた起きる。頻度の設計がそもそも合ってなかったわけです。

## 直したこと

確認を自分の記憶に任せるのをやめました。手元の版と最新版を比べて、違ったら教えるだけの短いスクリプトを書いて、毎朝走らせている別のスクリプトから呼ぶようにしました。

```zsh
LOCAL=$(claude --version | awk '{print $1}')
LATEST=$(npm view @anthropic-ai/claude-code version | grep -oE '^[0-9]+\.[0-9]+\.[0-9]+$' | tail -1)
[[ "$LOCAL" == "$LATEST" ]] && echo "✓ 最新" || echo "! 遅れている: $LOCAL / $LATEST"
```

自動更新そのものは、今回も戻していません。過去の自分が意図して切った可能性が残るので、**設定は変えずに検知だけ自動化**しました。遅れていることが毎朝目に入れば、更新するかどうかはその場で決められます。

## 書かなかったこと

6バージョンぶんで何が変わったかは調べていません。変更履歴を読んでいないので、「新しいのが出ている」以上のことは書けない。

あと、まだ更新していません。更新は他に影響が出ることがあるので、別の機会に。

## まとめ

人が思い出して確認する前提の運用は、だいたい動きません。先週「月1で確認する」と決めた自分は、たぶん本気でそう思ってた。でも6日で破綻した。

「確認する」と決めたときは、**何がそれを思い出させるのか**まで決めないと、決めた時点で終わってしまう。あと、診断ツールが「問題なし」と言っても、それは「自分が見ている範囲に問題がない」という意味でしかない。何を見ていないかの方が大事でした。
