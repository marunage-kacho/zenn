先週、Claude Code で Haiku 5.5 が使えるようになった日に、Sonnet と同じ仕事をさせて「安い方が正確だった」と X に書きました。
1回だけの話だったので、ちょっと気持ち悪くて...今日、5回ずつやり直しました。

結果から言うと、Sonnet は5回とも同じ数字を間違えて、Haiku は5回とも合ってました。
正直、逆の結果が出て「やっぱり気のせいでした」で終わると思ってたんですよ。

## やらせた仕事

副業で動かしている X アカウントの記録ファイルが4つあります。投稿ごとの表示数を書いた CSV、バズった投稿を見た記録、フォローした相手のリスト、フォロー候補のメモ。これを読んで「今朝の状況を5行で報告して」と頼む。毎朝自分でやってる作業です。

これを Haiku 5.5 と Sonnet に、同じ指示で3回ずつ。
それから、指示に「200字以内」を足したものを1回ずつ。
最後に、CSV だけ渡して「フォロワーの推移と、いちばん伸びた投稿は？」を1回ずつ。この CSV は空欄が多いので、わざと渡しました。

ツールはファイルを読むだけに絞って、`claude -p` で走らせています。

## 結果

| | Haiku 5.5 | Sonnet |
|---|---|---|
| 時間（1回あたり） | 12〜18秒 | 14〜17秒（CSVだけ渡した回は30秒） |
| 書く量 | Sonnet の3〜5倍 | 短い |
| 間違い | 5回中 0回 | 5回中 5回 |

Sonnet が間違えたのは毎回同じ場所で、「フォロー中 12」を「フォロワー 12」と読んでました。実際のフォロワーは1人です（少ないのは別の問題として）。

原因は CSV の空欄でした。「プロフィールクリック数」の列を埋めていない行があって、そこで列が1つずれて見えたらしい。
CSV だけ渡した回では、Sonnet は「followers_total 列が全行 12 になっていて、記録ミスの可能性が高い」と、こっちのせいにしてきました。自信たっぷりに。

Haiku は同じファイルで列を正しく読んで、しかも備考欄の「朝の行の表示9は固定ポストの値だった可能性」という小さいメモまで拾って、「個別の投稿としては数えにくい」と注釈を付けてきた。ここは、ちょっと感心した。

## 速さについての訂正

先週「Haiku の方が遅い」と書いたんですが、あれは Haiku が書く量が8倍だったせいでした。今回は出力が前回の半分くらいに落ち着いて、時間はほぼ同じ。
ただ、相変わらずよく書く。「200字以内」と指示しても、5行には収めてくるけど文は長い。短くしたいなら、行数じゃなくて「文の数」で指定した方がいい気がしています。

## 決めたこと

- ファイルを読んで数字を拾う作業は、Haiku にする。朝の数字まとめはスクリプトで Haiku 固定にした
- CSV の空欄を減らす。空欄が Sonnet を狂わせたなら、他のモデルも狂う
- 「大きい方が安全」という思い込みは捨てる。仕事の種類で選ぶ

## 書かなかったこと

コストは書いていません。手元の CLI が古くて、Haiku 5.5 の料金表を持っておらず、表示される金額が当てにならないからです。公式の発表値だけ見ると Haiku の方が安いのは確かなんですが、自分で測っていない数字は書かないことにしています。

あと、5回は「5回」でしかないです。10回やったら変わるかもしれない。でも、毎朝の作業で5回連続で同じ間違いをする相手には、もう頼まないかな...という程度の話です。
